# Демо без бэкенда (Vercel)

Фронт собирается в режиме `mock` и работает как статический сайт: вместо бэкенда на запросы отвечает мок прямо в
браузере. Данные — снапшот настоящего демо-стенда (около 290 пользователей, 413 встреч, клубы, блог, бобры),
изменения посетителя сохраняются в IndexedDB и переживают перезагрузку.

## Запуск

```bash
cd frontend
yarn dev:mock        # разработка, http://localhost:5173
yarn build:mock && yarn preview --port 4173   # как на Vercel
node scripts/mock-smoke.mjs                   # дымовой прогон в Chrome (вход, лента, запись, перезагрузка)
```

Деплой на Vercel: Root Directory `frontend`, Node 22, остальное берётся из `frontend/vercel.json`.
Карта работает с ключом `VITE_2GIS_KEY` в переменных проекта; без ключа показывается штатная заглушка.

## Как устроено

- `src/shared/api/mutators/authMutator.ts` при `VITE_MOCK` подставляет в axios адаптер `src/mock/adapter.ts`.
  Условие статическое: в обычной сборке код мока в бандл не попадает.
- `src/mock/core.ts` — запрос → маршрут из `routes.gen.ts` (генерируется из `openapi.json`: `yarn mock:routes`) → хендлер.
- `src/mock/services/` — порты сервисов Java-бэкенда (права, записи, серии по RRULE, награды, рекомендации,
  модерация, организации, блог, админка). Формулы и тексты ошибок те же, что у бэкенда.
- `src/mock/db/` — таблицы в памяти, персист в IndexedDB, сдвиг дат на целые недели к сегодняшнему дню.
- `src/mock/life/` — «живой мир»: на встречу по заявке приходят заявки и вопрос, организатор принимает заявки и
  отвечает на вопросы, администратор одобряет новый клуб. За 13 главных демо-аккаунтов мир не отвечает:
  эти роли проигрывает сам посетитель.
- Не поддержано (ответ 501 «В демо-версии это недоступно»): загрузка новых вещей бобра в админке, привязка
  Telegram, повторная проверка нейросетью. Вход через Яндекс и GitHub показывает подсказку.

## Снапшот

Снимается один раз с настоящего бэкенда с демо-данными:

```bash
make dev && make back        # дождаться «Demo data seeded», затем ещё пару минут (награды)
node scripts/mock-snapshot/export.mjs
```

Скрипт кладёт `frontend/src/mock/seed/snapshot.json` и фото в `frontend/public/media`. Фото — свободные
лицензии, список в `public/media/CREDITS.md`.

## Проверка

- `yarn mock:coverage` — у каждой операции из спеки есть хендлер.
- `node scripts/mock-diff.mjs [фильтр]` — одинаковые запросы к настоящему бэкенду (`:8080`) и к мок-ядру в Node,
  сравнение ответов. Сценарии чтения — `mock-diff/scenarios.mjs`, сценарии с записью — `mock-diff/flows-*.mjs`
  (перед ними БД бэкенда сбрасывается до дампа `real-data.dump`, см. `mock-diff/reset-real.sh`; дамп снимается `pg_dump -a -Fc` сразу после выгрузки снапшота).
